# 前端对接：统一认证登录（SSO）

> 适用版本：2026-11 起 ｜ 后端入口：`POST /auth/login` ｜ 相关接口：`GET /auth/profile`、`PUT /auth/password`、`POST /sync/sso/run`、`GET /sync/runs`

## 1. 这次改了什么

登录接口的**路径没变**，仍然是 `POST /auth/login`，但后端的行为变成了：

1. `authSource = local` 的账号（超管、管理员、历史本地账号）→ 直接本地密码校验，不调 SSO。
2. `authSource = sso` 的账号（教师、学生、首次登录自动建的号）→ 先调学校统一认证 `api-login`。
3. SSO 成功 → 后端回写本地姓名 / 部门 / 密码哈希，再签发本系统双令牌。
4. **只有网络不可达**（超时 / DNS / 连接失败 / TLS 握手失败）→ 回退本地密码。
5. SSO 明确返回密码错误、账号锁定、应用禁用、签名错误 → **不回退**，按错误码返回。

前端不需要自己跳 SSO 页面，也不需要保存 SSO 的 token。

## 2. 登录时序

```
前端                    本系统后端                      学校 SSO
 │  POST /auth/login       │                              │
 │  {username, password}   │                              │
 │ ──────────────────────> │                              │
 │                         │  authSource=local? ── 是 ──> 本地 bcrypt
 │                         │  否                          │
 │                         │  POST /sso/login/api-login   │
 │                         │ ───────────────────────────> │
 │                         │ <─────────────────────────── │
 │                         │                              │
 │                         │  成功：回写本地信息/密码      │
 │                         │  失败：按错误码分类          │
 │                         │    · 凭据拒绝 → 401，不回退   │
 │                         │    · 网络不可达 → 本地 bcrypt │
 │ <────────────────────── │                              │
 │  {accessToken, ...}     │                              │
```

## 3. 请求与响应

### 请求

```http
POST /auth/login
Content-Type: application/json

{
  "username": "20230001",
  "password": "用户输入的密码"
}
```

### 成功响应（`code = 0`）

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "accessToken": "eyJhbGciOiJIUzI1NiIs...",
    "refreshToken": "eyJhbGciOiJIUzI1NiIs...",
    "expiresIn": 7200,
    "loginSource": "sso",
    "ssoUnavailable": false,
    "isDefaultPwd": false
  }
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `loginSource` | `'sso' \| 'local' \| 'local-fallback'` | 本次登录来源 |
| `ssoUnavailable` | boolean | 是否因 SSO 不可用回退到本地密码 |
| `isDefaultPwd` | boolean \| null | SSO 返回的「是否仍用初始默认密码」；本地登录不返回 |

> 这三个字段只在 `POST /auth/login` 返回；`POST /auth/refresh` 与旧的 `/auth/sso/callback` 不返回。

## 4. 错误码与前端提示

| 错误码 | HTTP | 含义 | 前端提示建议 |
| --- | --- | --- | --- |
| 20101 | 401 | 用户名或密码错误（本地或 SSO 拒绝） | 「用户名或密码错误」 |
| 20102 | 401 | 账号已停用 | 「账号已停用，请联系管理员」 |
| 20103 | 401 | 登录失败次数过多 / SSO 账号锁定 | 「尝试次数过多，请 15 分钟后再试」 |
| 20104 | 401 | 登录态失效（刷新令牌时） | 清理本地令牌，回登录页 |
| 20105 | 400 | 原密码错误（改密时） | 「原密码错误」 |
| 20106 | 400 | 统一认证 state / 票据无效（浏览器跳转流程） | 「统一认证未通过，请重新登录」 |
| 20107 | 403 | SSO 通过但本系统没有对应账号，且不自动建号（如 admin/未知类型） | 「统一认证已通过，但本系统没有对应账号，请联系管理员」 |
| 20108 | 503 | 统一认证不可用且无法回退（本地无账号 / 回退关闭） | 「统一认证暂不可用，请稍后重试」 |
| 20109 | 502 | 统一认证配置异常（应用禁用 / 密钥错误 / 签名失败等） | 「统一认证配置异常，请联系管理员」 |
| 20110 | 429 | 统一认证请求过于频繁 | 「请求过于频繁，请稍后重试」 |
| 20111 | 502 | 统一认证返回异常 | 「统一认证返回异常，请稍后重试」 |
| 20112 | 403 | SSO 账号尝试本地改密 | 「统一认证账号请在统一认证平台修改密码」 |
| 20113 | 500 | 首次登录自动建号失败（部门/角色缺失等） | 「账号创建失败，请联系管理员」 |

> 后端不会把 SSO 的原始 `msg` 直接回显；前端按上表展示稳定文案即可。

## 5. 回退提示条

当 `ssoUnavailable === true` 时，说明本次是 **SSO 网络不可达、用本地缓存密码登录成功**：

```text
统一认证暂不可用，已使用本地密码登录
```

建议做成顶部黄色提示条，不阻塞用户；下一次登录成功（`loginSource === 'sso'`）后不再展示。

## 6. 默认密码提示

`isDefaultPwd === true` 时，SSO 判断用户仍在使用初始默认密码：

- 展示橙色提示条：「你仍在使用初始密码，请尽快到统一认证平台修改」。
- **不要拦截登录**，也不要把它当失败。
- 修改入口是学校统一认证平台，不是本系统的改密接口。

## 7. 改密入口

- 先调 `GET /auth/profile`，看 `data.user.authSource`：
  - `'sso'` → **隐藏/禁用**本系统「修改密码」入口，提示去统一认证平台改密。
  - `'local'` → 保持原有改密流程 `PUT /auth/password`。
- SSO 账号硬调 `PUT /auth/password` 会返回 403 / 20112。
- 管理员重置 `PUT /users/:id/password` 仍可用，但该密码会在下一次 SSO 登录成功时被覆盖；文档里不要把它宣传成长期密码。

## 8. 定时同步对前端的影响

后端会按配置的间隔从 SSO 同步组织、教师、学生：

- 用户的 `realName` / `deptId` 可能在同步后变化；页面展示前建议重新拉 `GET /auth/profile`。
- 账号可能被停用（源系统删人 / 毕业）：下一次请求会拿到 401 / 20102，前端清理令牌回登录页。
- 首次 SSO 登录会自动建号：
  - 教师（`userType=teacher`）默认绑定 `mentor` 角色；
  - 学生（`userType=student`）默认绑定 `student` 角色；
  - 不会自动给管理员角色。
- 本地账号（`authSource='local'`）不受 SSO 同步影响。

## 9. 手动同步（仅运维页）

只有超管或持有 `sync:run` 权限的账号可调：

```http
POST /sync/sso/run
Authorization: Bearer <accessToken>
Content-Type: application/json

{ "mode": "incremental" }   // 可选：incremental | full
```

响应 `202`：

```json
{ "code": 0, "data": { "runId": "42" } }
```

同步在后台执行，前端用 `GET /sync/runs?source=sso&page=1&pageSize=10` 查状态：

```json
{
  "code": 0,
  "data": {
    "rows": [
      {
        "id": "42",
        "source": "sso",
        "mode": "incremental",
        "status": 1,
        "startedAt": "2026-11-04T08:00:00.000Z",
        "finishedAt": "2026-11-04T08:01:12.000Z",
        "total": 1954,
        "okCount": 1950,
        "failCount": 4
      }
    ],
    "total": 1,
    "page": 1,
    "pageSize": 10
  }
}
```

`status`：`0 RUNNING / 1 OK / 2 PARTIAL / 3 FAILED`。响应**不返回**失败明细 `detail`。
