# v1 部署手册（后端 + 管理端 + 学生端）

> 适用：`mentor-back`（NestJS）+ `mentor-web`（管理端）+ `mentor-mobile`（学生端）
> 一台 Linux 服务器。脚本：`scripts/deploy/deploy.sh`。
> 示例配置：`scripts/deploy/deploy.env.example`、`scripts/deploy/mentor-back.service.example`、
> `scripts/deploy/nginx-mentor.conf.example`。
>
> **本文是 native 部署（systemd + nginx 静态目录）。用 Docker 部署见
> [部署-docker.md](部署-docker.md)。**

---

## 0. 架构与目录约定

```text
浏览器
  ├─ https://admin.example.com  ── nginx ── /var/www/mentor-web/current      (mentor-web)
  └─ https://m.example.com      ── nginx ── /var/www/mentor-mobile/current   (mentor-mobile)
                                  └─ /api/ 反代 → 127.0.0.1:3000 (mentor-back, systemd/pm2)
                                                   ├─ MySQL 8
                                                   └─ Redis
```

- 前端同源请求 `/api/`，nginx 剥掉前缀转给后端；**生产不需要配 CORS**。
- `/var/www/*/current` 是符号链接，指向 `releases/<时间戳>-web|mobile`；回滚只改链接。
- 源码与发布目录分开：源码在 `/opt/mentor/*`，发布产物在 `/var/www/*`。

## 1. 服务器基线

`deploy.sh` 启动时会**自动检查并安装**缺少的依赖（需要 sudo / root）：

| 依赖 | 处理 |
| --- | --- |
| curl / tar | 缺失时用 apt / dnf / yum / apk 安装 |
| nginx | 缺失时安装软件包（站点配置仍需手工做，见第 4 节） |
| Node.js | 缺失或 < 20 时安装 22 LTS（NodeSource；失败回退发行版包） |
| pnpm | 缺失时 `npm i -g pnpm@10` |
| MySQL / Redis | 已检测到则直接复用；仅当缺失且 `DATABASE_URL` / `REDIS_URL` 指向本机（localhost/127.0.0.1）时才安装 |

不想让脚本改服务器：加 `--check`（只检查）或 `--no-install`（缺依赖直接报错）。
MySQL 安装后仍需手工建库 / 建账号（见第 3 节）。

| 依赖 | 版本 / 说明 |
| --- | --- |
| OS | Linux（示例按 Ubuntu 22.04 / 24.04 写；CentOS 换对应包管理命令） |
| Node.js | **>= 20，推荐 22 LTS**（NestJS 11 要求） |
| pnpm | **>= 9**（三个仓库都用 pnpm-lock.yaml） |
| MySQL | 8.x，字符集 `utf8mb4` |
| Redis | 6.x 以上（会话版本、限流、权限缓存） |
| nginx | 任意稳定版 |
| curl | 部署脚本健康检查用 |

```bash
# Ubuntu 示例
sudo apt update
sudo apt install -y nginx mysql-server redis-server curl git
# Node 22 + pnpm：用 NodeSource 或 nvm 安装，确保部署用户 PATH 里能找到
node -v && pnpm -v
```

建部署用户与目录：

```bash
sudo useradd -m -s /bin/bash mentor   # 已存在就跳过
sudo mkdir -p /opt/mentor /var/www/mentor-web/releases /var/www/mentor-mobile/releases
sudo chown -R mentor:mentor /opt/mentor /var/www/mentor-web /var/www/mentor-mobile
```

> 如果发布目录只有 root 可写，在 `deploy.env` 里设 `SUDO=sudo`；否则留空。

## 2. 把源码放到服务器

后端是 git 仓库：

```bash
cd /opt/mentor
git clone git@github.com:fuguiRich/mentor-back.git
cd mentor-back && git checkout <v1 的提交或 tag>
```

管理端 / 学生端**当前不是 git 仓库**，需要从开发机同步源码（或构建后只传 `dist`）。
日常更新直接用 7.1 的 `deploy-remote.sh` 即可，它会自动上传；手工同步示例：

```bash
# 在开发机执行（Windows 可用 Git Bash / WSL；有 rsync 时优先 rsync）
rsync -az --delete \
  --exclude node_modules --exclude dist \
  ./mentor-web/  mentor@server:/opt/mentor/mentor-web/

rsync -az --delete \
  --exclude node_modules --exclude dist \
  ./mentor-mobile/  mentor@server:/opt/mentor/mentor-mobile/
```

没有 rsync 时用 `scp -r`（记得排除 `node_modules`、`dist`）；也可以在本机构建好，
只把 `dist` 传到服务器后跑 `deploy.sh web mobile --skip-build`。

## 3. 后端生产配置（`/opt/mentor/mentor-back/.env`）

**仓库里的 `.env` 是开发配置，不要直接上生产。** 在服务器上单独建一份：

```dotenv
NODE_ENV=production
PORT=3000

DATABASE_URL="mysql://mentor:<强密码>@127.0.0.1:3306/mentor_back"
REDIS_URL="redis://127.0.0.1:6379/0"

# 必填，>= 32 字符：openssl rand -base64 48
JWT_SECRET=<随机值>

# 文件落盘目录：绝对路径，且要纳入备份（部署脚本不会动它）
FILE_ROOT=/opt/mentor/data/uploads
FILE_MAX_BYTES=10485760

# 生产默认关 Swagger；内网要留再显式开
# SWAGGER_ENABLED=1

# 前端与后端同源（都走 nginx /api），CORS 基本用不到；
# 若还有别的来源直连后端，在这里列白名单
CORS_ORIGINS=https://admin.example.com,https://m.example.com

# SSO：按学校实际值填写；SSO_LOGIN_ENABLED=1 才走统一认证
SSO_LOGIN_ENABLED=1
SSO_BASE_URL=
SSO_APP_ID=
SSO_APP_SECRET=
SSO_PROVIDER=oidc
SSO_AUTHORIZE_URL=
SSO_TOKEN_URL=
SSO_USERINFO_URL=
SSO_CLIENT_ID=
SSO_CLIENT_SECRET=
SSO_REDIRECT_URI=https://admin.example.com/api/auth/sso/callback

# 定时同步（按需）
SSO_SYNC_ENABLED=1
```

```bash
sudo chown mentor:mentor /opt/mentor/mentor-back/.env
sudo chmod 600 /opt/mentor/mentor-back/.env
sudo mkdir -p /opt/mentor/data/uploads && sudo chown -R mentor:mentor /opt/mentor/data
```

> **不要**在服务器上设 `SEED_DEMO_DATA=1`：演示账号是公开密码，等于后门。
> `--seed` 只用来建初始超管（密码随机，只打印一次）。

数据库与 Redis：

```bash
sudo mysql -e "CREATE DATABASE mentor_back CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
sudo mysql -e "CREATE USER 'mentor'@'127.0.0.1' IDENTIFIED BY '<强密码>';
               GRANT ALL PRIVILEGES ON mentor_back.* TO 'mentor'@'127.0.0.1';
               FLUSH PRIVILEGES;"
redis-cli ping   # 应返回 PONG
```

## 4. 安装 systemd 服务与 nginx 站点

```bash
cd /opt/mentor/mentor-back

sudo cp scripts/deploy/mentor-back.service.example /etc/systemd/system/mentor-back.service
# 按实际部署用户 / node 路径（which node）修改，再：
sudo systemctl daemon-reload
sudo systemctl enable mentor-back
```

nginx 站点不用手工拷：在 `deploy.env` 里配好 `WEB_DOMAIN` / `MOBILE_DOMAIN` 后，
`deploy.sh` 会自动写 `/etc/nginx/conf.d/mentor-web.conf`、`mentor-mobile.conf`。
写之前会：

1. `nginx -t` 确认**现有**配置合法（服务器上还有其他项目）；
2. 检查 `server_name` 是否已被别的配置文件占用，冲突就中止；
3. 只覆盖/备份 `mentor-*.conf`，不碰其他站点；写后 `nginx -t` 失败自动回滚。

`NGINX_CONFIGURE=0` 时只做 `nginx -t + reload`，站点完全手工维护
（可参考 `scripts/deploy/nginx-mentor.conf.example`，注意它用的是 systemd/native 的静态目录）。

## 5. 配置部署脚本

```bash
cd /opt/mentor/mentor-back
cp scripts/deploy/deploy.env.example scripts/deploy/deploy.env
chmod 600 scripts/deploy/deploy.env
vi scripts/deploy/deploy.env
```

按服务器实际路径 / 进程管理方式修改（完整项见示例文件）。首次可先做只读检查：

```bash
bash scripts/deploy/deploy.sh all --check
```

> 走 SSH 自动部署时 `SUDO=sudo` 必须配成**免密**（sudoers 的 NOPASSWD），
> 否则脚本会卡在密码提示。最小授权示例见 `deploy.env.example` 的注释；
> 或者把发布目录 / 服务都交给部署用户，`SUDO` 留空。

## 6. 首次部署

```bash
cd /opt/mentor/mentor-back
bash scripts/deploy/deploy.sh all --seed
```

脚本按顺序做：

1. 后端：`pnpm install --frozen-lockfile` → `prisma generate` → `nest build`
2. `prisma migrate deploy`（建表；失败则中止，旧进程继续跑）
3. `pnpm db:seed`（仅 `--seed`；创建 super_admin，**随机密码只打印一次**，记下来）
4. 重启 systemd/pm2 → 轮询 `http://127.0.0.1:3000/health` 直到通过
5. 管理端：`VITE_API_BASE=/api pnpm build` → 发布到 `/var/www/mentor-web/releases/<ts>-web` → 切 `current`
6. 学生端：`VITE_API_BASE_URL=/api pnpm build` → 同上
7. `nginx -t && systemctl reload nginx`

首次部署后再把 admin 密码改掉，或直接在 seed 前设 `SEED_ADMIN_PASSWORD`（不推荐留默认）。

## 7. 日常更新

```bash
# 1) 后端：拉代码
cd /opt/mentor/mentor-back && git pull

# 2) 前端：开发机同步源码（命令见第 2 节）

# 3) 部署（可只发某端）
bash scripts/deploy/deploy.sh all
bash scripts/deploy/deploy.sh backend
bash scripts/deploy/deploy.sh web mobile
```

### 7.1 可选：从本地推送到远端

脚本本身是在服务器上运行的（第 5–7 节）。如果不想登录服务器手动传源码，
可以用本地编排脚本：本地只做 SSH + 源码同步，构建/迁移/重启仍在远端执行。

```bash
# 1) 本地一次配置（Windows 用 Git Bash 执行）
cp scripts/deploy/deploy-remote.env.example scripts/deploy/deploy-remote.env
#    填 REMOTE_HOST / REMOTE_USER / REMOTE_PORT
chmod 600 scripts/deploy/deploy-remote.env

# 2) 配置 SSH 免密（只需要做一次）
ssh-keygen -t ed25519          # 已有可跳过
ssh-copy-id -p 22 mentor@<server-ip>

# 3) 发布
bash scripts/deploy/deploy-remote.sh all
bash scripts/deploy/deploy-remote.sh all --seed     # 首次：远端建超管
bash scripts/deploy/deploy-remote.sh web mobile     # 只更新前端
bash scripts/deploy/deploy-remote.sh all --check    # 远端只检查
```

同步策略（`BACKEND_SYNC`）：

| 值 | 行为 | 适用 |
| --- | --- | --- |
| `git`（默认） | 远端 `git fetch/checkout/pull`，远端 `.env` 不动 | 正常迭代，要求本地分支已 push |
| `tar` | 上传本地工作区（含未提交改动），远端目录原子替换，保留 `.env` / `.uploads` / `scripts/deploy/deploy.env` | 还没推代码、紧急修一台机器 |

前端没有 git 仓库，固定走 `tar` 上传源码到 `/opt/mentor/mentor-web`、`/opt/mentor/mentor-mobile`，
再由远端脚本构建。本机需要 `ssh`、`tar`（Windows 11 自带 OpenSSH，Git Bash 自带 tar）。

常用参数：

| 参数 | 用途 |
| --- | --- |
| `--skip-migrate` | 确认本次没有迁移时跳过数据库步骤 |
| `--skip-build` | 前端用服务器上已有的 `dist`（离线环境 / 本机构建后上传） |
| `--with-tests` | 后端构建前跑 lint + tsc + 单测（生产机上通常不需要） |
| `--check` | 只检查目录、命令、Node 版本，不改任何东西（也不安装） |
| `--no-install` | 缺依赖时直接报错，不自动安装 |

## 9. 回滚

**前端**（秒级，保留最近 `KEEP_RELEASES` 份）：

```bash
ls -1dt /var/www/mentor-web/releases/*
sudo ln -sfn /var/www/mentor-web/releases/<上一份> /var/www/mentor-web/current
sudo systemctl reload nginx        # index.html 是 no-store，其实不 reload 也会生效
```

**后端**：

```bash
cd /opt/mentor/mentor-back
git checkout <上一个稳定提交>
bash scripts/deploy/deploy.sh backend --skip-migrate
```

> 数据库迁移**不会自动回滚**。破坏性迁移前先备份：
> `mysqldump --single-transaction mentor_back | gzip > backup-$(date +%F-%H%M).sql.gz`。
> 新增列 / 新表这类可向后兼容的迁移，旧代码通常还能跑；删列 / 改语义的迁移要先备份并评估。

## 10. v1 生产注意事项

- **HTTPS 必须**：登录、文件、SSO 回调都在明文上跑等于泄密。80 端口只做 301。
- **Swagger**：`NODE_ENV=production` 默认不挂载；内网确需时 `SWAGGER_ENABLED=1` 再在 nginx 放行。
- **上传目录**：`FILE_ROOT` 用绝对路径并纳入备份；重装 / 换机器时不能丢。
- **备份**：MySQL 每日 + `FILE_ROOT` 每日；Redis 只需会话 / 限流，可丢。
- **日志**：systemd 走 journald（`journalctl -u mentor-back -f`）；nginx 日志默认即可。
- **SSO**：生产启用后，`SSO_REDIRECT_URI` 必须是外网可访问的 https 地址，并在学校 SSO 后台登记。
- **权限**：`.env`、`deploy.env` 600；不要把密钥写进 git 或部署日志。
- **文档**：`docs/openapi.json` 是构建期快照，部署前在开发机 `pnpm docs:gen && git push`，
  后端拉代码时一起更新。
