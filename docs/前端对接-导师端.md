# 前端对接文档 —— 导师端

> **适用对象**：导师端（PC / 移动端 Web）前端开发。
> **覆盖范围**：P1 已实现并验收通过的接口 —— 导师专业档案、入驻申请、两级审核进度、佐证材料。
> **服务地址**：开发环境 `http://localhost:3001`（生产以部署为准）
> **在线文档**：`/api-docs`（Swagger，可直接试调；生产环境默认关闭）

---

## 1. 接入准备

### 1.1 跨域

后端 CORS 是**白名单**（fail-closed）。本地前端跑在 `http://localhost:5173` 已在白名单内；
换端口或换域名要后端加 `CORS_ORIGINS`，否则请求会被浏览器拦下（不是后端报错）。

### 1.2 鉴权流程

```
① POST /auth/login          → 拿 accessToken / refreshToken / expiresIn
② 之后每个请求带 Authorization: Bearer <accessToken>
③ accessToken 快过期（按 expiresIn 提前 60s）→ POST /auth/refresh
④ 用户退出 → POST /auth/logout（把 refreshToken 作废）
```

- **`expiresIn` 是 access 令牌的剩余秒数**，用它提前刷新，不要自己解 JWT。
- `POST /auth/refresh` 和 `POST /auth/login` 都是**免登录**的，不带 Authorization。
- **登录失败有锁定**：连续 5 次失败锁 15 分钟，锁定期内密码正确也拒绝。
  前端要能区分这三种 401（见 §4 错误码）。

### 1.3 登录后拉一次「我是谁」

```
GET /auth/profile
→ { user: {...}, permissions: string[], menus: [...] }
```

**`permissions` 是权限码数组**，导师端拿到的应该包含：

```
mentor:profile
mentor:profile-update
mentor-application:submit
mentor-application:withdraw
mentor-application:list
```

**用它驱动菜单与按钮的显隐**，不要在前端硬编码角色名。

## 2. 通用约定

### 2.1 统一响应外壳

**所有**接口（含错误）都是这个形状：

```json
{
  "code": 0,
  "message": "ok",
  "data": { },
  "traceId": "b7d48e94-2d63-4884-b96a-55fe92c6023b"
}
```

- `code === 0` 表示成功；**非 0 一律是失败**，即使 HTTP 是 200。
- `message` 是**可直接展示给用户**的中文文案（后端已经写好人话）。
- `traceId` 请记进前端错误日志——排查时要它才能对上服务端日志。

> **例外**：文件预览 / 下载返回的是**字节流**，不是这个外壳。

### 2.2 类型约定

| 类型 | 约定 | 例子 |
| --- | --- | --- |
| 大整数 ID | **字符串**，不要 `parseInt` | `"1234567890123456789"` |
| 时间 | **ISO 8601 UTC 字符串**，展示时自行转本地时区 | `"2026-10-29T03:00:00.000Z"` |
| 金额 | 本期无 | — |
| 枚举 | 数字，含义见 §6 | `status: 2` |

### 2.3 分页

请求：`?page=1&pageSize=20`（`page` 默认 1，`pageSize` 默认 20，**上限 100**）

响应 `data`：

```json
{ "list": [], "total": 0, "page": 1, "pageSize": 20 }
```

### 2.4 参数校验失败

`400` + `code = 10001`，`data.fields` **点名到字段**：

```json
{
  "code": 10001,
  "message": "参数校验失败",
  "data": {
    "fields": [
      { "field": "summary", "message": "summary 长度不能超过 2000 个字符" }
    ]
  }
}
```

前端应把 `fields[].message` 挂到对应输入框下方，而不是弹一个笼统的「参数错误」。

## 4. 错误码（前端需要区分的）

| code | HTTP | 含义 | 前端动作 |
| --- | --- | --- | --- |
| `10001` | 400 | 参数校验失败 | 读 `data.fields` 定位到字段 |
| `10002` | 401 | 未登录 / 令牌失效 | 清本地令牌 → 跳登录 |
| `10003` | 403 | 无权限 | 提示「无权限」；菜单本不该出现 |
| `10004` | 404 | 资源不存在 | 提示或回列表 |
| `10006` | 409 | 数据冲突（同一文件重复挂） | 提示「该材料已添加」 |
| `20101` | 401 | 用户名或密码错误 | 提示（**与不存在同码同文案**，别提示「用户不存在」） |
| `20102` | 401 | 账号已停用 | 提示联系管理员 |
| `20103` | 401 | 登录失败次数过多 | 提示稍后再试，可显示倒计时 |
| `20104` | 401 | refresh 令牌无效 | 清令牌 → 跳登录 |
| `20105` | 400 | 原密码错误 | 挂到「原密码」输入框 |
| `28101` | 404 | 文件不存在 | 提示文件已失效 |
| `28102` | 400 | 文件类型不允许 | 提示支持的类型 |
| `28103` | 400 | 文件过大 | 提示单文件上限 10 MB |
| `28104` | 400 | 空文件 | — |
| `28105` | 400 | 文件数超限 | 提示一次最多 10 个 |
| `28106` | 400 | 文件内容与扩展名不符 | 提示文件损坏或伪装 |
| `31102` | 404 | 导师档案不存在 | 引导去建档 |
| `31103` | 409 | 档案状态不允许修改 | 显示 `message` 原文（后端已分四种情形写好文案） |
| `31104` | 404 | 申请不存在 | 回列表 |
| `31105` | 409 | 当前状态不允许该操作 | 刷新详情后再决定 |
| `31106` | 409 | 已有在审的申请 | 提示「请先撤回在审申请」 |
| `31107` | 404 | 材料不存在 | 刷新列表 |
| `31201` | 404 | 时段不存在（含不是自己的） | 刷新时段列表 |
| `31206` | 409 | 该时段与已有开放时段重叠 | 提示重叠，让用户改时间 |

## 5. 接口详解

### 5.1 登录

> **统一认证（SSO）优先**：`SSO_LOGIN_ENABLED=true` 时，教师账号先走学校统一认证；
> 只有网络不可达才回退本地密码。响应新增 `loginSource` / `ssoUnavailable` / `isDefaultPwd`，
> 错误码 20108–20113 的含义与提示见 [前端对接-统一认证登录.md](./前端对接-统一认证登录.md)。

```
POST /auth/login
Content-Type: application/json

{ "username": "T002", "password": "******" }
```

`200` → `data`：

```json
{
  "accessToken": "eyJhbGciOi...",
  "refreshToken": "eyJhbGciOi...",
  "expiresIn": 7200
}
```

### 5.2 续期

```
POST /auth/refresh
{ "refreshToken": "..." }
```

`200` → 同登录的 `data`（新的双令牌）。

### 5.3 登出

```
POST /auth/logout
{ "refreshToken": "..." }
```

`200`。前端同时清掉本地两枚令牌。

### 5.4 当前用户

```
GET /auth/profile
```

`200` → `data`：

```json
{
  "user": {
    "id": "2", "username": "T002", "realName": "李思齐",
    "employeeNo": "T002", "mobile": null,
    "deptId": "2", "deptName": "计算机学院",
    "status": 1, "isSuperAdmin": false,
    "lastLoginAt": "2026-10-29T05:00:00.000Z",
    "createdAt": "2026-10-29T04:00:00.000Z"
  },
  "permissions": ["mentor:profile", "mentor:profile-update", "..."],
  "menus": []
}
```

### 5.5 查我的档案

```
GET /mentor/profile
```

`200` → `data`：

```json
{
  "id": "1",
  "personId": "1",
  "mentorType": "internal",
  "researchFields": ["软件工程", "人工智能"],
  "summary": "长期从事……",
  "achievements": "主持省部级项目 2 项……",
  "guidanceExperience": "指导研究生 12 名……",
  "affiliateOrg": null,
  "socialRoles": null,
  "professionalTitle": "教授",
  "contactMobile": "13800000000",
  "status": 2
}
```

**没有档案时是 `404 / 31102`**，前端据此进入「建档」流程，不要当成错误页。

### 5.6 建档 / 改草稿

```
PUT /mentor/profile
Content-Type: application/json

{
  "researchFields": ["软件工程"],
  "summary": "简介",
  "achievements": "成果",
  "guidanceExperience": "经历",
  "affiliateOrg": "合作单位",
  "socialRoles": "社会任职",
  "professionalTitle": "教授"
}
```

- **7 个字段全部可选**（增量语义）：省略 = 不改，显式 `null` = 清空。
- `researchFields` 传数组 = **整体替换**，最多 5 项、每项 ≤ 30 字符。
- `summary` / `achievements` / `guidanceExperience` ≤ 2000 字符。
- `affiliateOrg` / `socialRoles` ≤ 100 字符。
- `professionalTitle`（职称 / 资质）≤ 100 字符，**内校 / 外校都填**——不受下面
  内校置 `null` 那条规则影响（R28）。

**两个必知规则**：

1. **`mentorType` 由后端根据人员类型推导**（`internal` / `external`），**不要传**。
2. **内校导师（`internal`）的 `affiliateOrg` / `socialRoles` 会被落库成 `null`**，
   即使你传了值——回显也是 `null`。前端对 `mentorType === 'internal'` 应**隐藏这两个输入框**。
   外校导师（`external`）两个字段正常保存。

**状态门（关键）**：只有档案 `status` 为 `0 DRAFT` 或 `3 REJECTED` 时才能调本接口。
其余状态一律 `409 / 31103`，`message` 已分四种情形写好，直接展示即可：

| 档案 status | message |
| --- | --- |
| 1 PENDING | 导师专业档案在审，撤回后再改 |
| 2 APPROVED | 导师专业档案已生效，改字段走信息修改申请 |
| 4 FROZEN | 导师专业档案已冻结，不能修改 |
| 5 REMOVED | 导师专业档案已移除，不能修改 |

**禁止字段**：`status` / `personId` / `mentorType` / `id` 出现在请求体里 → `400 / 10001`。

### 5.6b 维护联系电话

```
PUT /mentor/profile/contact
Content-Type: application/json

{ "contactMobile": "13800138000" }
```

- **不走进驻 / 信息修改申请的审核流**，也不受 `status` 门约束——已生效导师随时可改。
- `contactMobile`：6-20 位，可含数字 / `+` / `-` / 空格 / 括号。
- **传 `null` 表示清除覆盖**，展示时回退到同步源的手机号。
- 未建档 → `404 / 31102`；调用者不是导师 → `403 / 10003`。
- 响应是完整档案对象（含 `contactMobile`）。
- 学生端导师详情里的 `mobile` 会优先取这个值，未填才回退 `SyncPerson.mobile`。

### 5.7 提交入驻申请

```
POST /mentor-applications
Content-Type: application/json

{}
```

- **没有请求体字段**（载荷由服务端按当前档案定死）。传任何字段 → `400 / 10001`。
- `201` → 申请对象（见 5.10），`type = 1`、`status = 2`。
- **副作用：档案 `status` 由 `0 → 1`**。
- 已有在审申请 → `409 / 31106`。
- 档案已生效（`status = 2`）→ `409 / 31103`（走 5.8 的信息修改申请）。

### 5.8 提交信息修改申请

```
POST /mentor-applications/profile-change
Content-Type: application/json

{ "summary": "改后的简介" }
```

- 请求体 = **与 `PUT /mentor/profile` 同一套字段**（增量语义）。
- **资格门：档案 `status` 必须是 `2 APPROVED`**。否则 `409 / 31103`。
- 有在审申请 → `409 / 31106`。
- `201` → 申请 `type = 2`、`status = 2`。**档案 `status` 不变**（仍为 2）。
- 审核通过那一刻才把字段写回档案。

### 5.9 我的申请列表

```
GET /mentor-applications?page=1&pageSize=20&status=2&type=1
```

- `status` / `type` 可选，见 §6 枚举。
- `200` → `data`：`{ list: [申请...], total, page, pageSize }`。
- **只返回自己的申请**（数据范围 `self`）。

### 5.10 申请详情

```
GET /mentor-applications/:id
```

`200` → `data`：

```json
{
  "id": "12",
  "type": 1,
  "applicantId": "2",
  "snapshot": {
    "mentorType": "external",
    "researchFields": ["语言学"],
    "summary": "……",
    "achievements": null,
    "guidanceExperience": null,
    "affiliateOrg": "某研究院",
    "socialRoles": null,
    "professionalTitle": "教授"
  },
  "status": 2,
  "collegeReview": null,
  "scReview": null,
  "submittedAt": "2026-10-29T05:10:00.000Z"
}
```

- **`snapshot` 是提交那一刻的完整 7 字段**，之后永不改写。前端应把「申请里的内容」和
  「当前档案内容」**分开展示**——已生效的申请是历史凭据。
- `collegeReview` / `scReview` 是审核记录，未审时为 `null`，审过后形如：

```json
{
  "reviewerId": "5",
  "reviewerName": "计算机学院管理员",
  "decision": "approve",
  "comment": "材料齐全，同意",
  "at": "2026-10-29T05:20:00.000Z"
}
```

### 5.11 撤回申请

```
POST /mentor-applications/:id/withdraw
Content-Type: application/json

{}
```

- 无请求体字段，传任何字段 → `400 / 10001`。
- 允许的状态：`2 COLLEGE_REVIEWING` / `3 COLLEGE_REJECTED` / `5 SC_REJECTED`。
- `200` → 申请变 `7 WITHDRAWN`。
- 其他状态 → `409 / 31105`。

### 5.12 上传文件

```
POST /files
Content-Type: multipart/form-data

files: <File>            ← 字段名必须是 files，可传 1–10 个
ownerType: MentorApplication
ownerId: <申请 id>
```

- **`ownerType` 必须是 `MentorApplication`**（PascalCase，大小写敏感）。
- `201` → `data` 是**数组**（即使只传一个）：

```json
[{
  "id": "31",
  "originName": "职称证书.pdf",
  "ext": "pdf",
  "mimeType": "application/pdf",
  "size": 204800,
  "sha256": "…",
  "uploaderId": "2",
  "ownerType": "MentorApplication",
  "ownerId": "12"
}]
```

**上传限制**：

| 项 | 值 |
| --- | --- |
| 单文件上限 | **10 MB** |
| 单次文件数 | **10 个** |
| 允许类型 | `png` `jpg` `jpeg` `gif` `webp` `bmp` `pdf` |

> **类型校验看文件头，不只看扩展名**（魔数校验）。把 `.exe` 改名成 `.pdf` 会被拒（`28106`）。

### 5.13 把文件挂到申请上

```
POST /mentor-applications/:id/materials
{ "fileId": "31", "kind": 1 }
```

- `kind`：**`1` 职称证书 / `2` 行业资质 / `3` 其他**，只认这三个值。
- `fileId` 必须**属于本申请**（上传时的 `ownerId` 要等于本申请 id），否则 `404 / 28101`。
- 只有 `status ∈ {2, 3}` 的申请能挂材料，其余 `409 / 31105`。
- 同一 `fileId` 重复挂 → `409 / 10006`。
- `201` → 材料对象（见 5.14）。

### 5.14 材料列表

```
GET /mentor-applications/:id/materials
```

**不收分页参数**，一次返回全部（条数有界）。`200` → `data`：

```json
{
  "list": [{
    "id": "7", "applicationId": "12", "fileId": "31",
    "kind": 1, "originName": "职称证书.pdf",
    "mimeType": "application/pdf", "size": 204800,
    "createdAt": "2026-10-29T05:12:00.000Z"
  }],
  "total": 1, "page": 1, "pageSize": 1
}
```

### 5.15 摘掉材料

```
DELETE /mentor-applications/:id/materials/:materialId
```

- **软删**：材料从列表消失，但文件本身还在（不会被连带删除）。
- 摘掉之后同一 `fileId` **可以再挂**。
- 状态门同 5.13（`{2,3}`）。

### 5.16 预览 / 下载

```
GET /mentor-applications/:id/materials/:materialId/preview
GET /mentor-applications/:id/materials/:materialId/download
```

- **返回字节流，不是 JSON**。
- `preview` → `Content-Disposition: inline`（PDF / 图片可直接内嵌 `<iframe>` / `<img>`）
- `download` → `attachment`，文件名是上传时的原名（含非 ASCII 字符时用 RFC 5987 编码，浏览器能正确处理）
- 前端用 `fetch` + `response.blob()` 或直接 `<a href>` 带 token 的方式（`<a>` 不会带 Authorization，
  需要用 `fetch` 拿 blob 再 `URL.createObjectURL`）。

### 5.17 可指导时段（P2）

```
GET    /mentor/slots
POST   /mentor/slots
PUT    /mentor/slots/:id
DELETE /mentor/slots/:id
```

**请求体（`POST` / `PUT`）**

```json
{ "weekday": 1, "startTime": "09:00", "endTime": "11:00", "status": 1 }
```

| 字段 | 取值 | 说明 |
| --- | --- | --- |
| `weekday` | **1-7**（1 = 周一） | 越界 → 400 |
| `startTime` / `endTime` | `HH:mm` | **`endTime` 必须严格大于 `startTime`** → 否则 400 |
| `status` | `1` 开放（默认）/ `0` 关闭 | 见下方「PUT 的 status 语义」 |

**响应**：`{ id, weekday, startTime, endTime, status }`

**`PUT` 的 `status` 语义（容易踩）**

- **省略 `status` = 保留原值**。所以「只想改时间」不会把关闭的时段悄悄打开。
- **`status: null` → 400**（不是「当没传」）。
- 关闭时段请显式传 `status: 0`。

**冲突**

- 同一导师**同一 weekday 的时段不能重叠**（半开区间 `[start, end)`）→ **409 / 31206**
  - `09:00-11:00` 已存在时，`11:00-12:00` **可以**（边界相接不算重叠），`10:00-12:00` **不行**
- 别人的时段 `PUT` / `DELETE` → **404 / 31201**（不是 403）

**其它**

- `GET` 不分页，一次返回全部时段。
- `DELETE` 是软删；删掉后同一时段可以重建。

## 7. 三条典型流程

### 7.1 首次入驻

```
① PUT  /mentor/profile                 建档（档案 0 DRAFT）
② POST /mentor-applications            提交（申请 2，档案 → 1 PENDING）
③ POST /files + POST .../materials     传材料挂材料
④ 等待：GET /mentor-applications/:id   轮询或刷新
   二级学院通过 → 申请 4；双创通过 → 申请 6，档案 → 2 APPROVED
```

### 7.2 被驳回后重提

```
① 收到申请 status = 3（COLLEGE_REJECTED），档案同时变 3
② PUT  /mentor/profile                 改档案（3 放行）
③ POST /mentor-applications            重新提交 → 新申请 status=2，档案 → 1
```

### 7.3 已生效后改信息

```
① 档案 status = 2 → PUT /mentor/profile 会 409
② POST /mentor-applications/profile-change   带要改的字段（增量）
   → 新申请 type=2、status=2；档案仍是 2
③ 审核通过后字段才写回档案
```

> **前端提示语**：档案已生效时，「编辑」按钮应引导到「提交信息修改申请」，而不是直接调 `PUT /mentor/profile`。

## 8. 前端落地建议

### 8.1 路由守卫

```ts
// 伪代码
if (!token) redirect('/login');
if (needPermission && !profile.permissions.includes(needPermission)) show403();
```

权限码从 `GET /auth/profile` 的 `permissions` 取，**不要硬编码角色名**。

### 8.2 401 的统一处理

拦截器里：`code === 10002 || code === 20104` → 清令牌 → 跳登录。
**不要**在 401 时弹 toast 让用户手动关，直接跳。

### 8.3 409 的处理

`31103` / `31105` / `31106` 都是**状态冲突**，不是 bug。处理方式：
刷新当前页面数据 → 用后端 `message` 提示 → 引导用户到正确入口。

### 8.4 别把 `snapshot` 当实时数据

申请详情里的 `snapshot` 是**提交时的历史快照**，可能与当前档案不同。
两个都展示时请明确标注（「申请时的内容」 vs 「当前档案」）。

## 9. 已知缺口（前端要提前知道）

1. **通用后台模块的权限码**：`config:*` 与 `assessment:rule-manage` 已补种并只绑
   `sc_admin`；`user:*` / `role:*` / `dept:*` / `dict:*` / `oplog:*` 仍不种。
   导师端需要的 `file:create` 已绑给 `mentor`；`file:list` 只给管理员
   （它没有按归属过滤，**不要**给导师端做文件管理页）。预约材料 / 成果佐证的
   预览下载走 §12 的专用路由，不依赖 `file:list`。
2. **`affiliateOrg` / `socialRoles` 对内校导师无效** —— 传了也会被落成 `null`。
   `professionalTitle` **不在此列**：内校导师照常填、照常回显（R28）。
3. **没有「删除档案」接口**，也没有「撤回已生效档案」——档案只增不删。
4. **材料列表不分页**，一次全返回。
5. **档案 `status` 的 `4 FROZEN` / `5 REMOVED` 目前没有入口**，前端按「只读」处理即可。

## 11. P2–P5 新增接口要点（2026-11-02）

完整字段与错误码以 `/api-docs` 为准；这里只列导师端容易接错的点。

### 11.1 预约处理（P2）

- `POST /appointments/:id/{confirm,reject,reschedule}`：有效出发态 `0 待确认`。
  `reject` 的 `rejectReason` 必填 1–500 字；`reschedule` 的 `proposedTime` 是 ISO 8601。
- `POST /appointments/:id/record`：从 `1 已确认` 推进到 `3 记录已提交`；
  `durationMinutes` 可选 1–600（不传落 0）。
- 列表 / 详情都是**导师视角**：只返回自己的预约。

### 11.2 评价（P3）

- `GET /mentors/:mentorId/reviews`：导师只能看自己的；分页 + 四个均值。
- 评价由学生写，导师**没有写入口**。

### 11.3 双创成果（P3）

- 只有导师本人能登记 / 修改 / 删除自己的成果（`:mentorId` 不是本人 → 404 / 31102）。
- `awardedAt` 是纯日期 `YYYY-MM-DD`，**不带时刻**。
- `type` 1 竞赛获奖 / 2 项目立项 / 3 其他；`level` 1 国家级 … 5 院级。

### 11.4 考核与申诉（P3 / P5）

- 考核周期是**学期 `YYYY-S`**（S=1 上半年 / 2 下半年），不再是四位年份。
- `GET /assessments`：`status = 0` 的行只回冻结兜底值，详情才是实时试算。
- 只有 `status = 2 已生效` 才能申诉；申诉**不改变**考核结果（受理 ≠ 重评）。
- 评分规则由双创学院配置（`PUT /assessments/rules`）；已提交的考核冻结提交时权重。

### 11.5 指导台账与工作台（P4）

- `GET /stats/guidance`：导师只能看自己的（`self`），传别人的 `mentorId` → 403。
- `GET /stats/workbench/:mentorId`：待确认 / 已确认 / 待学生确认、评价汇总、
  当前学期考核摘要、归档条目数。全部实时值。

### 11.6 消息 / 学生成果 / 归档（P5）

- 消息：`GET /messages` 只回自己的；`unread` 是未读总数；标记别人的消息 → 404 / 38001。
- 学生成果：导师只能看**关联到自己**的成果（`self`），不能登记 / 关联。
- 归档：导师只能看自己的归档（`self`）。

## 12. 导师端缺口补齐（2026-11-05）

> 完整说明见 `docs/优化文档-导师端接口缺口.md`；这里只列前端接法。

### 12.1 预约材料 / 过程材料预览下载

```http
GET /appointments/{id}/materials/{materialId}/preview
GET /appointments/{id}/materials/{materialId}/download
GET /appointments/{id}/record/materials/{materialId}/preview
GET /appointments/{id}/record/materials/{materialId}/download
```

- 权限码 `appointment:list`；返回**字节流**，可见性与材料列表一致。
- 预约材料不存在 → 404 / 32005；过程材料不存在 → 404 / 33002。

### 12.2 成果佐证预览下载

```http
GET /mentors/{mentorId}/achievements/{achievementId}/proof/preview
GET /mentors/{mentorId}/achievements/{achievementId}/proof/download
```

- 权限码 `achievement:list`；没有佐证文件 → 404 / 28101。

### 12.3 指导记录列表 / 导出

```http
GET /mentor/records?page=1&pageSize=20&from=&to=&type=
GET /mentor/records/export?from=&to=&type=
```

- 权限码 `appointment:list`；只返回本人导师档案的记录，按 `actualTime` 倒序。
- 列表字段：`appointmentId`、`studentName`、`studentLogin`、`type`、`status`、
  `actualTime`、`mode`、`coreContent`、`followUp`、`durationMinutes`。
- 导出 CSV 表头：`预约ID,学生,学号,预约类型,实际指导时间,指导方式,时长(分钟),核心指导内容,后续指导建议`；
  超过 `export.max_rows` → 409 / 37004。

### 12.4 `GET /auth/profile` 新增人员类型

`user` 里新增：

- `personType`：`teacher` / `internalMentor` / `externalMentor` / `student` / `null`；
- `mentorType`：`internal` / `external` / `null`。

建档前用它决定 `affiliateOrg` / `socialRoles` 是否显示。

### 12.5 草稿阶段上传佐证

1. `POST /files` 先传文件（此时无归属）；
2. `POST /mentor-applications` 提交申请；
3. `POST /mentor-applications/{id}/materials` 用同一个 `fileId` 挂接——上传人本人会被
   允许认领这个无归属文件。

### 12.6 申请详情

申请人本人读 `GET /mentor-applications/{id}` 不再 403，无需再回退到列表查找。
控制器仍要求 `mentor-application:list`（导师角色已默认持有）。

### 12.7 联系电话维护（2026-11-07）

```http
PUT /mentor/profile/contact
{ "contactMobile": "13800138000" }
```

- 权限码 `mentor:profile-update`；**不走进驻 / 信息修改申请的审核流**，也不受档案
  `status` 门约束；
- `contactMobile`：6-20 位，可含数字 / `+` / `-` / 空格 / 括号；
- 传 `null` = 清除覆盖，展示时回退到同步源 `SyncPerson.mobile`；
- `GET /mentor/profile` 返回 `contactMobile`；学生端导师详情的 `mobile`
  优先取该值，未填回退同步手机号。
