## 1. 预约材料 / 过程材料预览与下载

### 新增接口

```http
GET /appointments/{id}/materials/{materialId}/preview
GET /appointments/{id}/materials/{materialId}/download
GET /appointments/{id}/record/materials/{materialId}/preview
GET /appointments/{id}/record/materials/{materialId}/download
```

- **返回字节流，不是统一响应外壳**（`@NoEnvelope`）。
- `preview`：`Content-Disposition: inline`，PDF / 图片可直接放进 `<iframe>` / `<img>`。
- `download`：`Content-Disposition: attachment`，文件名是上传时的原名。
- 权限码：`appointment:list`（导师角色已有），数据范围天花板 `all`，服务层按预约可见性收窄。
- 可见性：**申请人本人 / 该预约导师本人 / 数据范围覆盖申请人部门的管理员**，与
  `GET /appointments/{id}/materials` 完全一致。
- 归属校验：材料行对应的 `SysFile` 必须归属 `Appointment` + 该预约 id；不匹配按 404 处理。

### 错误

| 情形 | HTTP / code |
| --- | --- |
| 缺 `appointment:list` | 403 / 10003 |
| 预约不存在 / 已软删 | 404 / 32001 |
| 不在可见范围 | 403 / 32002（`无权访问该预约`） |
| 预约材料不存在 / 已软删 / 不属于本预约 | 404 / 32005 |
| 过程材料不存在 / 已软删 / 不属于本记录 | 404 / 33002 |
| 文件本体已清理 | 404 / 28101 |

> 前端不要再调用通用 `GET /files/{id}/preview|download`。那组接口要求 `file:list`，
> 且没有按预约归属过滤，导师端不应持有该权限。

## 2. 成果佐证预览与下载

### 新增接口

```http
GET /mentors/{mentorId}/achievements/{achievementId}/proof/preview
GET /mentors/{mentorId}/achievements/{achievementId}/proof/download
```

- 返回字节流；`preview` 行内、`download` 附件。
- 权限码：`achievement:list`；数据范围天花板 `all`，服务层按导师部门可见性收窄。
- 可见性：导师本人 / 数据范围覆盖导师部门的管理员，与成果列表一致。
- 只服务**该成果自己的 `proofFileId`**；成果没有佐证 → 404 / 28101。

### 错误

| 情形 | HTTP / code |
| --- | --- |
| 导师档案不存在 / 未生效 | 404 / 31102 |
| 不在数据范围 | 403 / 10003 |
| 成果不存在 / 不属于该导师 | 404 / 36001 |
| 成果没有佐证文件 | 404 / 28101 |

## 3. 导师指导记录列表

### 新增接口

```http
GET /mentor/records?page=1&pageSize=20&from=2026-01-01T00:00:00.000Z&to=2026-12-31T23:59:59.999Z&type=1
```

- 权限码：`appointment:list`；`@DataScope('self')`。
- 只返回**调用者本人导师档案**名下的记录，不需要也不接受 `mentorId` 入参。
- 排序：`actualTime DESC, id DESC`。
- 筛选：
  - `from` / `to`：实际指导时间的 ISO 8601 上下界（含边界）；
  - `type`：预约类型 1–5。
- 不是导师（解析不出本人档案）→ **403 / 32002**。

### 响应

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "list": [
      {
        "appointmentId": "15021",
        "studentName": "陈一鸣",
        "studentLogin": "S001",
        "type": 1,
        "status": 6,
        "actualTime": "2026-11-05T12:10:21.654Z",
        "mode": 2,
        "coreContent": "……",
        "followUp": "……",
        "durationMinutes": 60
      }
    ],
    "total": 12,
    "page": 1,
    "pageSize": 20
  }
}
```

> 这条接口直接替代「先拉预约列表、再逐条查记录」的 N+1 调用。

## 4. 个人指导台账明细导出

### 新增接口

```http
GET /mentor/records/export?from=&to=&type=
```

- 与列表**同一套筛选与可见性**，不分页，一次导出全部命中记录。
- 权限码：`appointment:list`；`@DataScope('self')`。
- 返回 CSV（UTF-8 + BOM），文件名形如 `mentor-records-self-20261105.csv`。
- 表头固定 9 列：

  ```
  预约ID,学生,学号,预约类型,实际指导时间,指导方式,时长(分钟),核心指导内容,后续指导建议
  ```

- 超过 `export.max_rows`（默认 50000）→ **409 / 37004**，不静默截断。

> 与 `GET /stats/guidance/export` 的区别：后者是**聚合统计**（按导师 / 类型汇总），
> 本接口是**逐条台账**。

## 5. `GET /auth/profile` 增加人员类型

### 现有接口扩展

`GET /auth/profile` 的 `user` 对象新增两个只读字段：

```json
{
  "user": {
    "...": "原有字段不变",
    "personType": "teacher",
    "mentorType": "internal"
  },
  "permissions": ["..."],
  "menus": ["..."]
}
```

| 字段 | 取值 | 说明 |
| --- | --- | --- |
| `personType` | `teacher` / `internalMentor` / `externalMentor` / `student` / `null` | 源系统人员类型；查不到 `SyncPerson` 时为 `null` |
| `mentorType` | `internal` / `external` / `null` | `teacher`、`internalMentor` → `internal`；`externalMentor` → `external`；其余 `null` |

前端可以在**首次建档前**就决定是否展示 / 隐藏 `affiliateOrg`、`socialRoles`：

- `mentorType === 'external'`：显示两个字段；
- `mentorType === 'internal'`：隐藏（传了后端也会落 `null`）；
- `null`：按未知处理，建议先展示并提示「保存后按人员类型校正」。

## 6. 草稿阶段上传佐证材料

### 现有接口行为扩展

原流程的问题是：材料只能挂到**已提交的申请**上，而草稿档案还没有申请 id。
现在支持**先上传、后认领**：

```http
# ① 建档阶段：上传文件，不带归属
POST /files
Content-Type: multipart/form-data
files=@职称证书.pdf

# → 201，返回 SysFile（ownerType / ownerId 为 null）

# ② 保存并提交入驻申请
POST /mentor-applications
# → 201，拿到 applicationId，status = 2 COLLEGE_REVIEWING

# ③ 把草稿期上传的文件挂到申请上
POST /mentor-applications/{applicationId}/materials
{ "fileId": "<① 的 id>", "kind": 1 }
```

第 ③ 步的认领规则：

- 文件**无归属**且 `createdBy` 是调用者本人 → 认领给本申请（写
  `ownerType = 'MentorApplication'`、`ownerId = applicationId`）；
- 文件已归属**本申请** → 幂等通过；
- 文件归属其他对象 / 由别人上传 → 404 / 28101（不泄露文件是否存在）。

这样前端可以在建档页直接提供「上传佐证」按钮，文件先落在临时区，提交后再绑定。
注意：**认领发生在第 ③ 步**，提交申请本身不会自动绑定草稿期上传的文件。

## 7. 跨申请材料列表（暂不新增）

`GET /mentor/materials?kind=&page=&pageSize=` 属于**可选**需求，当前产品未确认是否需要
「我的全部佐证材料」页面，本次不实现。

现有可替代方案：

- 按申请查：`GET /mentor-applications/{id}/materials`；
- 申请列表：`GET /mentor-applications`，逐条取材料（材料条数有界，通常个位数）。

如果后续确认要做，建议沿用 `appointment:list` 之外的独立权限码，避免把材料面摊给
所有能看申请的人；届时再补接口与文档。

## 8. 申请人本人读取申请详情

### 现有接口修复

`GET /mentor-applications/{id}` 之前对申请人本人返回 **403 / 10003**，原因是服务层
只按部门数据范围判断，而 `self` 范围没有 `deptIds`。

修复后：

- 控制器仍要求 `mentor-application:list`（导师角色在 seed 中已持有该权限码，
  与列表接口一致）；
- 服务层先判断**调用者是否该申请的申请人本人**，是则直接放行；
- 非申请人再走原来的 `assertDeptVisible`：不可见 → 403 / 10003，不存在 → 404 / 31104。

前端不再需要「详情 403 就回退到列表里按 id 查找」的兜底逻辑，可以直接用详情接口。

> 如果某个自定义角色只给了 `mentor-application:submit` 而没给 `list`，详情仍会在
> 权限守卫处 403。这是权限配置问题，不是数据范围问题。

## 9. teacher 账号读档案 403（数据同步问题）

`GET /mentor/profile` 的身份门接受 `personType ∈ {internalMentor, externalMentor, teacher}`，
**不是**接口限制。实测 403 的账号是因为**没有对应的 `SyncPerson`**：

- 人员类型来自 `SyncPerson.personType`；
- 手工通过 `POST /users/account` 建的账号只建登录态，不建 `SyncPerson`；
- SSO 定时同步会为教师创建 `SyncPerson`（`personType = teacher`），同步完成后即可建档。

处理建议：

1. 确认该账号在 SSO / 源系统中存在，并已被同步任务覆盖；
2. 触发一次同步：`POST /sync/sso/run`（或在管理端执行定时同步）；
3. 同步后重新登录，`GET /auth/profile` 的 `personType` 应变为 `teacher`。

本次**不新增**「手工建号时自动建 `SyncPerson`」的逻辑：人员数据归源系统，
在登录模块里补人员行会让投影与同步源漂移。

## 10. 权限矩阵（新增接口）

| 接口 | 权限码 | 数据范围天花板 | 服务层收窄 |
| --- | --- | --- | --- |
| `GET /appointments/{id}/materials/{materialId}/preview|download` | `appointment:list` | `all` | 预约可见性 |
| `GET /appointments/{id}/record/materials/{materialId}/preview|download` | `appointment:list` | `all` | 预约可见性 |
| `GET /mentors/{mentorId}/achievements/{achievementId}/proof/preview|download` | `achievement:list` | `all` | 导师部门可见性 |
| `GET /mentor/records` | `appointment:list` | `self` | 本人导师档案 |
| `GET /mentor/records/export` | `appointment:list` | `self` | 本人导师档案 |
| `GET /mentor-applications/{id}`（修复） | `mentor-application:list` | `all` | 申请人本人直接放行，其余按部门 |

导师角色（seed 中的 `mentor`）已包含上述权限码，无需额外授权。

## 11. 前端改造清单

1. **材料列表**：预约材料 / 过程材料的「预览 / 下载」按钮解除置灰，改调 §1 的四个新路由。
2. **成果列表**：`proofFileId != null` 时显示「查看佐证 / 下载」，改调 §2 的两个新路由。
3. **指导记录页**：用 `GET /mentor/records` 一次取列表，删除 N+1 查询；筛选参数
   `from` / `to` / `type` 直接透传。
4. **台账导出**：用 `GET /mentor/records/export` 替代 `/stats/guidance/export`；
   收到 409 / 37004 时提示缩小时间范围。
5. **建档表单**：登录后读 `user.mentorType`，提前决定 `affiliateOrg` / `socialRoles`
   的显隐；`null` 时按未知处理。
6. **建档上传**：提供「上传佐证」按钮，先 `POST /files`，提交申请后再
   `POST /mentor-applications/{id}/materials` 绑定。
7. **申请详情**：删除「403 回退列表查找」的兜底，直接使用详情响应。

## 12. 兼容性

- 所有改动都是**新增路由 / 新增字段 / 放宽既有校验**，没有删除或改名既有字段。
- `GET /auth/profile` 的原有字段保持不变；新增字段对旧前端无影响。
- `POST /mentor-applications/{id}/materials` 对「已归属本申请」的文件仍然幂等，
  原调用方式不受影响。
- 文件预览 / 下载仍是字节流，不套统一响应外壳。
