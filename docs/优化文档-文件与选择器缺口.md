## 1. 归档附件

### 数据

`archive_item.file_ids`（JSON 数组，存 `SysFile.id`）。文件本体不复制、不删除，
归档软删时也不连带删文件。

### 写

```http
POST /files                 # 1-10 个文件，返回 fileId
POST /archives
{
  "targetType": "StudentAchievement",
  "targetId": "9",
  "title": "学生省级竞赛成果",
  "category": "other",
  "fileIds": ["12"]
}
```

- `fileIds` 可省略；传 `[]` 表示没有附件；
- 文件不存在 / 已软删 → 400 / 28101；
- `targetType` 白名单新增 `StudentAchievement`（自动归档写入的类型现在也能手工选）。

`PATCH /archives/:id` 同样接受 `fileIds`：

```json
{ "fileIds": ["12", "13"] }
```

传 `[]` 清空附件。

### 读 / 预览 / 下载

归档响应新增：

```json
{
  "fileIds": ["12"],
  "files": [
    {
      "id": "12",
      "originName": "获奖证书.pdf",
      "mimeType": "application/pdf",
      "size": 102400
    }
  ]
}
```

```http
GET /archives/:id/files/:fileId/preview
GET /archives/:id/files/:fileId/download
```

- 权限码 `archive:list`；
- 可见性与归档详情一致（`all` / 本院 / 本人）；
- `fileId` 必须在该归档的 `fileIds` 中，否则 404 / 28101。

### 核心 / 非核心切换

```http
PATCH /archives/:id/core
{ "core": 1 }
```

- `core = 1`：永久保存，`retentionUntil` 清空；
- `core = 0`：从今天重新计算保留期（`archive.noncore_retention_days`，默认 1825 天）；
- 权限码 `archive:manage`，前端归档详情抽屉有「设为核心 / 设为非核心」按钮。

### 学生成果自动归档

学生成果关联导师时，自动生成的归档条目会带上该成果的佐证：

```text
StudentAchievement.proofFileId → archive_item.fileIds = [proofFileId]
```

归档详情 / 附件预览下载会直接显示学生成果的佐证材料。

历史数据由 `npm run db:seed` 回填：日志出现 `学生成果归档附件回填：N 条`。

## 2. 考核申诉佐证

### 数据

`assessment_appeal.file_ids`（JSON 数组）。

### 写

```http
POST /files                 # 导师本人上传
POST /assessments/:id/appeals
{
  "reason": "初评遗漏了下半年的省级奖项。",
  "fileIds": ["12", "13"]
}
```

- 只允许引用**本人上传**的文件；别人的 fileId → 404 / 28101；
- 申诉响应新增 `fileIds` / `files`，同时已有 `assessment`、`submittedBy`、`handledBy` 实体。

### 预览 / 下载

```http
GET /assessments/:id/appeals/:appealId/files/:fileId/preview
GET /assessments/:id/appeals/:appealId/files/:fileId/download
```

- 权限码 `assessment:list`；
- 可见性与考核详情一致；
- `fileId` 必须在该申诉的 `fileIds` 中，否则 404 / 28101。

## 3. 学生成果佐证上传权限

问题：`POST /files` 需要 `file:create`，而 `college_admin` / `sc_admin` 之前只有
`file:list`，登记学生成果时上传佐证会 403。

处理：seed 已给两个管理员角色补 `file:create`。重新执行：

```bash
npm run db:seed
```

前端不再需要根据 `file:create` 隐藏上传区域（已有权限判断可保留，作为兜底）。

## 4. 学生下拉目录

```http
GET /student-achievements/students?keyword=陈&deptId=2&page=1&pageSize=20
```

响应：

```json
{
  "list": [
    {
      "id": "5",
      "login": "20230001",
      "realName": "陈一鸣",
      "deptId": "2",
      "deptName": "计算机学院",
      "major": "软件工程",
      "className": "软工 2023-1 班"
    }
  ],
  "total": 1,
  "page": 1,
  "pageSize": 20
}
```

- 权限码 `student-achievement:list`；
- 数据范围：双创学院看全校；学院管理员只看本院；
- 指定外院 `deptId` → 403 / 10003；
- 导师 / 学生账号返回空列表，不暴露学生目录。

> 归档「学生成果」目标、学生成果登记 / 筛选都可以改用它，不再只依赖
> `/appointments` 与 `/student-achievements` 的已有数据。

## 5. 暂不新增的两项

### 5.1 指导记录全局检索

前端当前**不提供** `GuidanceRecord` 作为手工归档目标，避免用户手填记录 ID。
现有 `GET /mentor/records`（导师本人）与 `/me/records`（学生本人）已够各自页面用。
若后续要开放，再补：

```http
GET /guidance-records?mentorId=&from=&to=&page=&pageSize=
```

### 5.2 双创成果全局检索

前端已采用「先选导师 → 再选成果」的两级下拉，不需要跨导师按成果名搜索。
若后续需要统一搜索，再补：

```http
GET /achievements?keyword=&mentorId=&page=&pageSize=
```

---

## 6. 权限与兼容性

- 所有新增字段 / 路由都是**增量**：原有 `POST/PATCH /archives` 不传 `fileIds` 时行为不变；
- `ArchiveItem` / `AssessmentAppeal` 旧行 `file_ids` 为 NULL，响应按 `[]` 处理；
- 文件预览 / 下载返回字节流，不套统一响应外壳；
- 删除归档 / 申诉不会删除 `SysFile`（文件可能被多处引用）。
