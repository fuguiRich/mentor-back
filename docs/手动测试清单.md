# 手动测试清单 —— 按角色逐一验

> 面向人工验收。每条都是「一条断言」，期望值写在右边。
> **状态码口径**：`401` 未登录、`403` 已登录但没权限、`404` 找不到、`409` 状态冲突、`400` 入参不合法。
> **错误码**：`10003` FORBIDDEN、`10001` PARAM_INVALID、`31103` 档案状态不允许、`31105` 申请状态不允许、`31106` 已有在审申请、`31102` 档案不存在、`31107` 材料不存在。

## 11. 已知边界（测到这些不是 bug）

1. **`MentorProfile.status` 的 `4 FROZEN` / `5 REMOVED` 没有任何入口** —— 计划没要求，故意不给。
2. **通用后台模块的权限码**：`config:*` 与 `assessment:rule-manage` 已补种并只绑
   `sc_admin`；`user:*` / `role:*` / `permission:*` / `dept:*` / `dict:*` / `oplog:*`
   仍不种（除超管外没人能调）。
   `file:create` 已绑 `mentor` / `student`；`file:list` 只绑 `college_admin` / `sc_admin`
   ——它**没有按归属过滤**，不要给导师 / 学生。
   **例外**：`file:create` 已种并绑给 `mentor` 角色——导师传佐证材料要走 `POST /files`，不绑就是死路。
3. **材料挂接只在 `status ∈ {2, 3}` 允许**，`{4,5,6,7}` 一律 **409 / 31105**。
4. **`T001` 的 `PUT /mentor/profile` 必然 409** —— 档案已生效，这是 R55 的设计。
5. **`/api-docs` 在 `NODE_ENV=production` 下默认 404**（本机是开发环境，所以能看到）。
6. **并发重复挂同一文件**：顺序执行第二次是 409 / 10006；**并发**可能插两行（已知缺口，见台账 R81）。
