# 前端对接文档 —— 学生端

> **适用对象**：学生端（移动端 / PC Web）前端开发。
> **服务地址**：开发环境 `http://localhost:3001`（生产以部署为准）
> **在线文档**：`/api-docs`（Swagger；生产环境默认关闭）
> **版本**：P1–P5 已交付（2026-11-02）；学生端接口缺口补齐（2026-11-06）
>
> **接口缺口**：已补齐可预约时段、预约时间范围筛选、跨预约记录列表、学生专业/班级、
> 成果佐证下载；「导师改期后的学生响应」仍待产品确认状态机。详见
> [优化文档-学生端接口缺口.md](./优化文档-学生端接口缺口.md)。

## 0. 先看这一句

学生端业务接口**已全部上线**：导师检索、预约、记录确认 / 异议、评价、
个人档案导出、消息、学生成果查询。字段与错误码以 `/api-docs` 为准，


## 1. 认证（5 条）

| # | 方法 | 路径 | 说明 |
| --- | --- | --- | --- |
| 1 | POST | `/auth/login` | 用户名（学号）+ 密码登录 |
| 2 | POST | `/auth/refresh` | 续期 |
| 3 | POST | `/auth/logout` | 登出 |
| 4 | GET | `/auth/profile` | 当前用户 + 权限码 + 菜单 |
| 5 | PUT | `/auth/password` | 改自己的密码 |

`POST /auth/login` 的 `username` 是**学号**（同步源 `login`）；
「学号不存在」与「密码错误」同码同文案（`20101`），不要提示「该学号未注册」。
连续 5 次失败锁 15 分钟。

> **统一认证（SSO）优先**：`SSO_LOGIN_ENABLED=true` 时学生账号先走学校统一认证；
> 只有网络不可达才回退本地密码。响应新增 `loginSource` / `ssoUnavailable` / `isDefaultPwd`，
> 错误码 20108–20113 的含义与提示见 [前端对接-统一认证登录.md](./前端对接-统一认证登录.md)。

`GET /auth/profile` 的 `user` 还包含学生档案字段：`major`（专业）、`className`
（行政班级）、`orgUnitName`（所属学院 / 组织）。未同步到人员行时为 `null`。

## 2. 导师检索（§2.1）

| 方法 | 路径 | 权限码 | 说明 |
| --- | --- | --- | --- |
| GET | `/mentors` | `mentor:search` | 分页检索：姓名 / 单位 / 研究领域 / 指导方向 / 职称 / 可指导时段 |
| GET | `/mentors/{id}` | `mentor:search` | 导师详情（简介、研究成果、指导经历、时段） |

- 只返回**已生效**导师（`status = 2`）。
- `id` 是 `MentorProfile.id`，BIGINT 对外字符串。
- **详情返回 `timeSlots`**：当前开放（`status = 1`）且未软删的时段，按
  `weekday` / `startTime` 升序。发起预约时取 `timeSlots[].id` 作为 `slotId`。
  学生不需要也不应该调用 `/mentor/slots`（权限码 `mentor:slot-manage` 只给导师）。

## 3. 预约（§2.2–§2.4）

| 方法 | 路径 | 权限码 | 说明 |
| --- | --- | --- | --- |
| POST | `/appointments` | `appointment:create` | 发起预约 |
| GET | `/appointments` | `appointment:list` | 我的预约列表（学生视角） |
| GET | `/appointments/{id}` | `appointment:list` | 预约详情 |
| POST | `/appointments/{id}/cancel` | `appointment:create` | 取消 |
| GET | `/appointments/{id}/record` | `appointment:list` | 看导师填写的指导记录 |
| POST | `/appointments/{id}/confirm-record` | `appointment:create` | 确认记录 |
| POST | `/appointments/{id}/dispute` | `appointment:create` | 对记录提异议 |
| POST | `/appointments/{id}/materials` | `appointment:create` | 挂预约材料 |
| GET | `/appointments/{id}/materials` | `appointment:list` | 材料列表 |
| DELETE | `/appointments/{id}/materials/{materialId}` | `appointment:create` | 摘材料 |

**发起预约请求体**：`{ mentorProfileId, slotId, type, requestedTime, topic, questions, mode }`
- `type` 1 双创竞赛 / 2 科研项目 / 3 创业实践 / 4 论文·专利 / 5 其他
- `mode` 1 线上 / 2 线下
- `requestedTime` 是 ISO 8601 **UTC 时刻**；必须落在导师开放时段的 weekday 与区间内
  （按 `APP_TIMEZONE` 解释墙钟时间）。

**列表筛选**：`GET /appointments` 支持 `status` / `type` / `from` / `to`（AND）。
`from` / `to` 按 `requestedTime` 过滤，ISO 8601；纯日期 `to` 含当天
`23:59:59.999`（UTC）。`from` 晚于 `to` → 400 / 10001。

**状态机**（`status`）：

```
0 待导师确认 → 1 已确认 → 3 记录已提交（待学生确认）
            → 4 学生已确认 → 6 已完成
0/1 → 7 已拒绝 / 8 已取消 / 9 已过期
3 → 5 有异议 → 复核后回到 4 或 6
```

**上传材料**：先 `POST /files`（multipart，字段名 `files`，单次 1–10 个）拿到 `fileId`，
再挂到预约上。学生**没有** `file:list`，不能走文件管理页；
材料列表会返回 `fileId / originName / mimeType / size`。

**材料预览 / 下载**：不要调用通用 `GET /files/{id}/preview|download`（需要 `file:list`）。
预约材料用 `GET /appointments/{id}/materials/{materialId}/preview|download`；
过程材料用 `GET /appointments/{id}/record/materials/{materialId}/preview|download`。

## 4. 评价（§2.5）

| 方法 | 路径 | 权限码 | 说明 |
| --- | --- | --- | --- |
| POST | `/appointments/{id}/review` | `review:create` | 对已完成指导评价 |
| GET | `/appointments/{id}/review` | `review:list` | 查看评价 |
| GET | `/mentors/{mentorId}/reviews` | `review:list` | 某导师的评价列表与均值 |

**请求体**：`{ attitude, expertise, effect, comment? }`，三个维度 1–5；
`overallScore` 由后端算（保留 2 位），不要自己传。
只有预约状态 `4 学生已确认` 才能评价；评价与 `4 → 6` 同事务。

## 5. 个人统计与导出（§2.6）

| 方法 | 路径 | 权限码 | 说明 |
| --- | --- | --- | --- |
| GET | `/stats/guidance` | `stats:guidance` | 个人指导台账（`self` 范围，学生无导师档案时为空集） |
| GET | `/me/records` | `stats:guidance` | 我的指导记录明细（JSON，分页） |
| GET | `/me/reviews` | `stats:guidance` | 我的评价列表（JSON，分页） |
| GET | `/me/records/export` | `stats:guidance` | 导出个人指导档案 CSV |

`/me/records` 只含本人 `status = 6` 的预约，字段：`appointmentId`、`mentorName`、
`type` / `typeLabel`、`topic`、`actualTime`、`durationMinutes`、`attitude` /
`expertise` / `effect` / `overallScore` / `comment`（未填为 `null`）。
`from` / `to` 按实际指导时间过滤；`type` 1–5。

`/me/reviews` 只含本人写过的评价，按评价时间倒序；`from` / `to` 按评价时间过滤。

CSV：UTF-8 + BOM，表头
`预约ID,导师姓名,预约类型,指导主题,实际指导时间,指导时长(分钟),我的评分,我的评价`。
只含本人 `status = 6` 的预约。

| 方法 | 路径 | 权限码 | 说明 |
| --- | --- | --- | --- |
| GET | `/messages` | `message:list` | 我的消息；`read=0/1`、`type=1/2/3`、分页 |
| PATCH | `/messages/{id}/read` | `message:list` | 标记已读（已读回执） |

## 7. 学生成果（§5.4）

| 方法 | 路径 | 权限码 | 说明 |
| --- | --- | --- | --- |
| GET | `/student-achievements` | `student-achievement:list` | 只看自己的成果 |
| GET | `/student-achievements/{id}/proof/preview` | `student-achievement:list` | 预览佐证（字节流） |
| GET | `/student-achievements/{id}/proof/download` | `student-achievement:list` | 下载佐证（字节流） |

按学生 / 导师 / 类型 / 年份 / 关联状态筛选；`self` 范围自动收窄到本人。

佐证预览 / 下载不需要 `file:list`；没有佐证或文件已清理 → 404 / 28101。

## 8. 通用约定

### 8.1 统一响应外壳

```json
{ "code": 0, "message": "ok", "data": {}, "traceId": "..." }
```

`code === 0` 才算成功，HTTP 200 不代表业务成功。

### 8.2 类型

| 类型 | 约定 |
| --- | --- |
| 大整数 ID | **字符串**，不要 `parseInt` |
| 时间 | ISO 8601 UTC；展示转本地时区 |
| 日期 | `YYYY-MM-DD`（不带时刻） |
| 分页 | `?page=1&pageSize=20`（上限 100） |

### 8.3 错误码

| code | HTTP | 含义 |
| --- | --- | --- |
| `10001` | 400 | 参数校验失败（`data.fields` 点名到字段） |
| `10002` | 401 | 未登录 / 令牌失效 |
| `10003` | 403 | 无权限 |
| `10004` | 404 | 资源不存在 |
| `20101` | 401 | 学号或密码错误（不区分学号不存在） |
| `20102` | 401 | 账号已停用 |
| `20103` | 401 | 登录失败次数过多 |
| `32002` | 403 | 预约不属于本人 / 不在可见范围 |
| `32003` | 409 | 当前状态不允许该操作 |
| `34001` | 404 | 该预约还没有评价 |
| `34002` | 409 | 该预约已评价过 |
| `38001` | 404 | 消息不存在 / 不属于本人 |
