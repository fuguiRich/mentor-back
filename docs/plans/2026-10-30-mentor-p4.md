## P4 的裁决（**全部可推翻**，改一处即可）

| # | 歧义 | 裁决 | 理由 | 推翻代价 |
| ---: | --- | --- | --- | --- |
| **R60** | 「导出」是什么格式 | **CSV（UTF-8 + BOM）**，`Content-Type: text/csv; charset=utf-8` | 零依赖、可流式、Excel / WPS 双击即开。引一个 xlsx 库只为换个后缀，收益不抵维护成本；真要 xlsx 就在同一路由上加 `?format=xlsx` 一个分支 | 加一个依赖 + 一个分支 |
| **R61** | 导出的文件名 | **一律 ASCII**：`<resource>-<period|all>-<yyyymmdd>.csv`，如 `mentor-stats-2026-20261031.csv` | 非 ASCII 文件名要走 RFC 5987 编码，写错就是 `Content-Disposition` 头注入面；ASCII 没有这个问题 | 改一处拼名函数 |
| **R62** | 导出上限 | `export.max_rows`（`SysConfig`）默认 **50000**；超出 → **409 / 37004**，**不静默截断** | 静默截断会让「导出名单」少人而无人察觉——这是报表类系统最危险的失败模式 | 改成截断 + 响应头提示 |
| **R63** | 「预约成功率」「指导完成率」怎么算 | `acceptanceRate`（预约成功率）= `count(status ∈ {1,2,3,4,5,6}) / count(all)`；`completionRate`（指导完成率）= `count(status = 6) / count(status ∈ {6,7,8,9})`。均为 2 位小数，**分母为 0 → `null`**（不是 0） | 需求 §5.3 只给了名字没给公式。两条分母不同：前者衡量「导师接不接」，后者衡量「接了的做没做完」 | 改两个分母集合 |
| **R64** | 什么材料算「核心」 | `core = 1`：入驻审核材料、考核档案（`targetType ∈ {'MentorApplication','Assessment'}`）；`core = 0`：指导记录、双创成果、其他 | §4.7 要「长期保存」，§6.5 要「清理过期**非核心**材料」。两条并存只有一个解释：核心永久、非核心到期清 | 改一处判定 |
| **R65** | 过期清理删什么 | **只软删 `archive_item` 行**，**绝不删 `SysFile`** | `SysFile` 被多处引用（申请材料、过程材料、成果佐证），按归档条目删文件会连带删掉别处的引用 | 改成级联删文件（危险） |
| **R66** | 归档写入是自动还是手工 | **两条都要**：两个审核通过点自动归档（`MentorApplication → 2`、`Assessment → 2`），同事务；其余由管理员手工归档 | §4.7「审核通过材料**统一**归档」——靠人点做不到「统一」；手工入口留给归档范围外的材料 | 去掉自动挂点 |
| **R67** | 指导方向分布怎么统计 | **应用层聚合**：分页读 `mentor_profile.research_fields`（每批 500），JS 计数 | 该列是 JSON 数组，Prisma 无「任意下标展开」；`path: '$[i]'` 要写死上限（R29 已裁定不用），`JSON_TABLE` 是裸 SQL（R78 只放行 `SELECT … FOR UPDATE`）。导师量级是千级，JS 聚合不构成瓶颈 | 加派生文本列 + 迁移 |
| **R68** | 「活跃 / 非活跃导师」的判据 | 生效档案（`status = 2`）在**统计周期内**有 **≥1 条 `status = 6` 的预约** → 活跃；否则非活跃 | §4.1 只列了「活跃 / 非活跃导师数」没给定义。用「有没有真的指导完一次」是最不容易被质疑的口径 | 改一处条件 |
| **R69** | 学生能不能看别人的数据 | **不能**。§2.6 的个人记录 / 档案导出一律 `self`；学生没有任何跨人视图 | §2.6 原文是「**个人**预约记录、指导记录、评价记录」 | 放开数据范围（危险） |
| **R70** | 统计的时间维度 | 统一用 `period`（`^\d{4}$`，与 P3 的 R47 同一口径）**或** `from` / `to`（`YYYY-MM-DD`，闭区间转成 `[from 00:00:00, to+1day 00:00:00)`）。二者**互斥**，同时传 → 400 / 10001；都不传 → 当年 | 需求反复说「按时间段」「按学期 / 年度」。两种口径都给、由调用方选，比只给一种更贴近原文；互斥校验防止口径打架 | 只留一种 |

### 统计口径的三条硬规则

1. **空集不返回 0**：均值 / 比率类字段在分母为 0 时返回 `null`，只有计数类字段返回 `0`。
   把「没人评」显示成「0 分」是报表系统最常见的谎。
2. **十态全列**：`byStatus` 必须列全 0–9 十个状态，计数为 0 的也要出现。
   前端直接按状态画图，缺项会让图表的轴忽长忽短。
3. **只算未删行**：所有统计走 `prisma.client`（软删扩展已生效），不得用 `includingDeleted`。

### Task 45: 导师资源库统计

**Files:**
- Create: `src/modules/stats/{stats.module.ts,stats.controller.ts,stats.service.ts}`
- Create: `src/modules/stats/research-field.util.ts`（**指导方向聚合的唯一实现**，Task 48 复用它）
- Create: `src/modules/stats/dto/{stats-query.dto.ts,mentor-stats.dto.ts}`

**Interfaces:**
- Produces：
  ```ts
  /** 分页读完 mentor_profile.research_fields（每批 500），返回 mentorId → 方向数组（**已去重**） */
  export function loadResearchFields(mentorIds: bigint[]): Promise<Map<string, string[]>>;
  ```
  Task 48 的 `byResearchField` **必须**用这个 loader 取方向，不许再写一份 JSON 展开——
  两处的去重口径不一致时，「同一导师多个方向各计一次」这条判据会在两个接口上给出两个答案。

**路由**：`GET /stats/mentors`，权限码 `stats:mentor`，范围 `dept` / `all`

**查询参数**：`period?`（`^\d{4}$`，默认当年）/ `from?` / `to?`（R70 互斥）/ `deptId?`（仅 `all` 可用）/ `mentorType?`（`internal` / `external`）

**响应**

```ts
{
  total: number;                 // 生效档案（status = 2）总数
  internal: number;              // 其中 personType = 'internalMentor'
  external: number;              // 其中 personType = 'externalMentor'
  byStatus: {                    // MentorProfile.status 全 6 态，缺项补 0
    draft: number; pending: number; approved: number;
    rejected: number; frozen: number; removed: number;
  };
  active: number;                // R68
  inactive: number;              // 生效档案 − 活跃
  byResearchField: { field: string; count: number }[];  // 按 count 倒序，同数按 field 升序（R67）
}
```

**判据**
- [ ] `byStatus` 六个键**全部存在**（断言 `Object.keys` 全集），即使某态为 0
- [ ] `byResearchField` 的 `count` 之和 **≥** `total`（一个导师多个方向，可以大于）
- [ ] 同一导师 `researchFields = ['A','A']` → 只计一次 A（**去重**）
- [ ] 学院管理员看到的 `total` 只含本院
- [ ] `from > to` → 400 / 10001；`period` 与 `from` 同时传 → 400 / 10001
- [ ] `deptId` 由学院管理员传 → 403 / 10003（越权指定范围）

### Task 50: 导出框架 + 全部导出路由

**Files:**
- Create: `src/modules/stats/export/{csv.writer.ts,csv.writer.spec.ts}`
- Modify: `src/modules/stats/{stats.controller.ts,stats.service.ts}`

**`csv.writer.ts` 契约（纯函数，可单测）**

```ts
export function csvEscape(value: unknown): string;
export function writeCsv(stream: NodeJS.WritableStream, rows: AsyncIterable<unknown[]>, headers: string[]): Promise<void>;
```

- 首行写 **UTF-8 BOM（`﻿`）** + 表头（R60）
- 转义按 RFC 4180：含 `,` / `"` / `\n` / `\r` 的字段用 `"` 包裹，内部 `"` 变 `""`
- **CSV 注入防护**：字段值以 `=` / `+` / `-` / `@` / `\t` / `\r` 开头时，前置一个 `'`
- `null` / `undefined` → 空串；`Date` → `YYYY-MM-DD HH:mm:ss`（本地时区）

> **上限必须先判后写**（R62 的落地方式）：路由**先跑一次 `count`**，`count > export.max_rows`
> → 直接抛 **409 / 37004**，**一个字节都不写**。不许「边写边数、超了就抛」——
> 那时响应头和 BOM 已经发出去了，HTTP 状态码改不成 409，客户端只会拿到一份被截断的 CSV。

### Task 53: 归档管理 + 过期清理

**Files:**
- Modify: `src/modules/archive/{archive.controller.ts,archive.service.ts,archive.repository.ts}`

**路由**

| 方法 | 路径 | 权限码 | 说明 |
| --- | --- | --- | --- |
| PATCH | `/archives/:id` | `archive:manage` | 改 `title` / `summary` / `retentionUntil` |
| DELETE | `/archives/:id` | `archive:manage` | 软删（取消归档） |
| POST | `/archives/purge` | `archive:manage` | 执行一次过期清理，返回 `{ purged: number }` |

**清理规则（R65）**
- 候选：`deleted_at IS NULL` AND `core = 0` AND `retentionUntil IS NOT NULL` AND `retentionUntil < 今天`
- 「今天」按 **`APP_TIMEZONE`**（默认 `Asia/Shanghai`）算，不按 UTC——
  与 P2 的 R31 同一口径，否则北京时间 00:00–08:00 之间清理会比预期晚一天
- **只软删 `archive_item`**；**不碰 `SysFile`**
- 清理是幂等的：连跑两次，第二次 `purged = 0`
- 手动触发 + 定时任务各一条路径；定时任务走既有的扫描框架（`appointment.appointmentExpiry` 同一套），开关 `archive.purge_enabled` 默认**关**（生产先人工跑）

> **路由顺序**：`POST /archives/purge` 必须声明在 `@Patch(':id')` / `@Delete(':id')` **之前**。
> 本期三个方法不冲突（`purge` 只有 POST），但一旦以后给 `purge` 加 GET，`/archives/:id`
> 会先匹配到它并把 `purge` 当成 id。写成 `@Post('purge')` 放在类的最上方，把这条顺序钉死。

**判据**
- [ ] `core = 1` 的条目**永不**被清理（造一条 10 年前的核心条目 → `purged` 不含它）
- [ ] `retentionUntil = 今天` → 不清理（严格小于）
- [ ] 连跑两次 → 第二次 `purged = 0`
- [ ] 清理后 `SysFile` 行**仍在**（R65 可伪性探针：把清理改成同时删文件 → 判据必须转红）
- [ ] 删除归档后，同一 `(targetType, targetId)` 可再归档
