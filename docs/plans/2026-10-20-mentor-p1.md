# mentor-back · P0 + P1 实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development
> 步骤用复选框（`- [ ]`）语法跟踪。
> **节奏**：每完成一个任务停下来，向委托人报「已完成 / 未完成」清单，由委托人决定是否继续。

**Goal:** 在 mentor-back 落地同步 / 数据权限 / 文件存储地基，交付「导师专业档案 + 两级入驻审核」。

**Architecture:** mentor-back 是独立工程，**通用后台的源码就在它自己仓库里**（`src/{config,common,infra,modules}` + `test/`），要改就改，运行时不依赖任何后台包。Prisma schema 归本项目持有。本项目新增同步层（`SyncOrgUnit` / `SyncPerson` / `SyncRun`）与业务层（导师档案、申请、材料）。用户与组织架构由外部接口定期同步落库，同步完**投影**到 `SysUser` / `SysDept`（见 §2.4）。

**Tech Stack:** NestJS 11 / TypeScript 5.7 / pnpm / Prisma + MySQL 8 / Redis / Jest 30 + supertest

**投影（R2 / R3 / R4，规格 §2.4）**
- `SyncOrgUnit` → `SysDept`：`id` / `name` / `parentId` 一一对应；源系统软删 → `SysDept` 软删。
- `SyncPerson` → `SysUser`：工号 / 学号作 `username`，姓名作 `realName`，`orgUnitId` 对到 `deptId`，`personType` 决定默认角色。

**Ruling（N1/N2/N3）**：
- **N1 源系统删行 → 软删**（`deleted_at`）。历史业务数据（他名下的预约、指导记录）仍能关联到人，不跟着消失。
- **N2 增量优先，接口给不出增量就退全量。** `SyncRun` 两种都记 `total`。
- **N3 不留姓名 / 学院的历史快照。** 「按学院统计」按**统计当时**的组织归属算；要历史口径再加快照表，别提前建。

**判据**
- 一次同步跑通，`SyncRun` 落一条 `status=OK|PARTIAL|FAILED`
- **失败明细可见**：`SyncRun.detail` 存 JSON（失败行 + 原因），**不静默吞**（ERR-07）
- **幂等**：同一批数据跑两次，表内容不变（要有专门用例）
- 软删用例：源系统删人 → `deleted_at` 落值 → 该人名下的历史预约仍可查
- **投影用例**：同步一批人 → `SysUser` 出现对应账号且能登录；源系统删人 → 账号停用但不消失

### Task 13: 入驻申请提交

**Files:**
- Create: `mentor-back/src/modules/mentor-application/`（`dto/` `mentor-application.controller.ts` `mentor-application.service.ts` `mentor-application.repository.ts`）

// POST /mentor-applications  body: SubmitOnboardDto
// → MentorApplicationResponseDto

**精确值**

**判据**

- 快照不可变用例：提交后改档案，申请里的 `snapshot` 不变

### Task 14: 两级审核流（状态机）

**Ruling #5**：**两级审**（二级学院 → 双创学院），与入驻一致。

**Files:**
- Create: `mentor-back/src/modules/mentor-application/review.service.ts`
- Modify: `mentor-back/src/modules/oplog/`（审核动作落 `SysOpLog`，R7）

**状态机（精确，非法流转一律拒）**

```text
SUBMITTED(1)
  → COLLEGE_REVIEWING(2)   系统自动
  → COLLEGE_REJECTED(3)    二级学院 不通过（必填意见）→ 退回申请人
  → SC_REVIEWING(4)        二级学院 通过
  → SC_REJECTED(5)         双创学院 不通过（必填意见）→ 退回二级学院重审
  → APPROVED(6)            双创学院 通过 → 回写 MentorProfile.status = 2
  → WITHDRAWN(7)           申请人撤回（仅在 1/2/3 状态可撤）
```

**安全（必守）**
- **只有二级学院管理员能操作 2→3 / 2→4**；**只有双创学院管理员能操作 4→5 / 4→6**——越权要 403，不是 404（要能区分「没权限」和「不存在」）
- 二级学院管理员只能审**本院**导师的申请（`@DataScope('dept')`）
- 每次审核动作**必须**落 `SysOpLog`

**判据**
- 通过路径与退回路径都走通
- **越权用例**：二级学院管理员试图操作 4→6 → 403
- **非法流转用例**：从 `3 COLLEGE_REJECTED` 直接 `→ APPROVED` → 拒
- 退回后申请人能改并重新提交
