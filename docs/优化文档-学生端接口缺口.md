## 1. 导师开放时段（已补齐）

### 实现方式

`GET /mentors/{id}` 的详情响应新增 `timeSlots`，前端不需要再调
`GET /mentor/slots`（那个接口的权限码是 `mentor:slot-manage`，学生无权限）。

```json
{
  "id": "1",
  "name": "张明远",
  "...": "原有字段不变",
  "timeSlots": [
    {
      "id": "12",
      "mentorProfileId": "1",
      "weekday": 3,
      "startTime": "09:00",
      "endTime": "11:00",
      "status": 1
    }
  ]
}
```

- 只返回 `status = 1`（开放）且未软删的时段；
- 按 `weekday` / `startTime` / `id` 升序；
- 权限码仍是 `mentor:search`；导师不存在 / 未生效 → 404 / 31102；
- 发起预约时直接取 `timeSlots[].id` 作为 `slotId`。

> 前端 `MentorDetail` 已预留 `timeSlots?: MentorTimeSlot[]`，字段补齐后无需改结构。

## 2. 预约列表按时间段筛选（已补齐）

### 扩展后的参数

```http
GET /appointments?page=1&pageSize=20&from=2026-01-01&to=2026-12-31&type=1&status=6
```

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `from` | ISO 8601 | 起始时间，含；按 `requestedTime` 过滤 |
| `to` | ISO 8601 | 结束时间，含；纯日期表示当天 `23:59:59.999`（UTC） |
| `type` | 1–5 | 已有 |
| `status` | 0–9 | 已有 |

- 所有条件 **AND**；`from` / `to` 可以只传一个；
- `from` 晚于 `to` → **400 / 10001**，消息 `from 必须不晚于 to`；
- 学生 `self` 范围不变；
- 纯日期按 UTC 零点解释；需要东八区墙钟时间请传带偏移的 ISO 8601，
  例如 `2026-01-01T00:00:00+08:00`。

## 3. 跨预约的指导记录 / 评价列表（已补齐）

### 3.1 `GET /me/records`

```http
GET /me/records?page=1&pageSize=20&from=2026-01-01&to=2026-12-31&type=1
```

- 权限码：`stats:guidance`；数据范围 `self`；
- 只返回调用者本人 `status = 6 COMPLETED` 的预约；
- `from` / `to` 按**实际指导时间** `GuidanceRecord.actualTime` 过滤；
- 排序：`requestedTime DESC, id DESC`。

响应：

```json
{
  "list": [
    {
      "appointmentId": "1",
      "mentorProfileId": "1",
      "mentorName": "张明远",
      "type": 1,
      "typeLabel": "双创竞赛指导",
      "topic": "挑战杯项目选题与打磨",
      "actualTime": "2026-11-01T02:00:00.000Z",
      "durationMinutes": 60,
      "attitude": 5,
      "expertise": 4,
      "effect": 4,
      "overallScore": "4.33",
      "comment": "讲解清晰。"
    }
  ],
  "total": 1,
  "page": 1,
  "pageSize": 20
}
```

- 没有指导记录时 `actualTime` / `durationMinutes` 为 `null`；
- 没有评价时四个评分字段与 `comment` 为 `null`；
- 不是学生（解析不出 `SyncPerson` 或 `personType != 'student'`）→ **403 / 10003**。

### 3.2 `GET /me/reviews`

```http
GET /me/reviews?page=1&pageSize=20&from=2026-01-01&to=2026-12-31&type=1
```

- 权限码：`stats:guidance`；数据范围 `self`；
- 只返回调用者本人写过的评价；
- `from` / `to` 按**评价时间** `StudentReview.createdAt` 过滤；
- 排序：`createdAt DESC, id DESC`。

响应：

```json
{
  "list": [
    {
      "id": "1",
      "appointmentId": "1",
      "mentorProfileId": "1",
      "mentorName": "张明远",
      "type": 1,
      "typeLabel": "双创竞赛指导",
      "topic": "挑战杯项目选题与打磨",
      "attitude": 5,
      "expertise": 4,
      "effect": 4,
      "overallScore": "4.33",
      "comment": "讲解清晰。",
      "createdAt": "2026-11-01T03:00:00.000Z"
    }
  ],
  "total": 1,
  "page": 1,
  "pageSize": 20
}
```

> 「指导档案」页可以不再解析 `/me/records/export` 的 CSV，直接切到这两个 JSON 接口。
> 导出接口保留，用于下载。

## 4. 学生档案专业 / 行政班级（已补齐）

`GET /auth/profile` 的 `user` 新增三个只读字段：

```json
{
  "user": {
    "...": "原有字段不变",
    "personType": "student",
    "mentorType": null,
    "major": "软件工程",
    "className": "软工 2023-1 班",
    "orgUnitName": "软件学院"
  },
  "permissions": ["..."],
  "menus": ["..."]
}
```

| 字段 | 来源 | 说明 |
| --- | --- | --- |
| `major` | `SyncPerson.major` | 专业；未填为 `null` |
| `className` | `SyncPerson.class_name` | 行政班级；未填为 `null` |
| `orgUnitName` | `SyncOrgUnit.name` | 所属学院 / 组织名称 |

- 查不到 `SyncPerson` 时三个字段都是 `null`，不报错；
- 原有字段保持不变，旧前端不受影响。

## 5. 学生成果佐证预览 / 下载（已补齐）

### 新增接口

```http
GET /student-achievements/{id}/proof/preview
GET /student-achievements/{id}/proof/download
```

- 权限码：`student-achievement:list`；数据范围天花板 `all`，服务层按列表同一套
  可见性收窄（本人 / 本院管理员 / 双创学院管理员）；
- 返回字节流；`preview` 行内、`download` 附件；
- 成果不存在 / 不属于可见范围 / 没有佐证 / 文件已清理 → **404**：
  - 成果不存在 → 404 / 39001；
  - 没有 `proofFileId` 或文件已清理 → 404 / 28101。

### 前端接法

成果卡片在 `proofFileId != null` 时显示「预览 / 下载」，按接口返回的
`Content-Disposition` 处理即可；不需要 `file:list`。

## 6. 导师改期后的学生响应（待产品确认，本次未实现）

### 现状

- 导师 `POST /appointments/{id}/reschedule` 只更新 `proposedTime` 与
  `handleComment`，预约仍停在 `0 PENDING`，`requestedTime` 不变；
- 学生端没有接受 / 拒绝改期的接口。

### 为什么没有直接加接口

这不是纯接口缺口，而是**状态机缺口**。至少要先回答：

1. 学生接受后预约进入哪个状态——`1 CONFIRMED`，还是仍留在 `0 PENDING`
   等导师再确认？
2. 学生拒绝后回到哪个状态——保留原时间继续 `0 PENDING`，还是直接
   `8 CANCELLED`？
3. 拒绝原因是否要持久化、是否要通知导师？
4. `proposedTime` 接受后是否写回 `requestedTime`？

不同答案会产生不同的数据形态和前端交互，贸然实现会把错误的状态机固化进库。

### 建议方案（待确认后实施）

```http
POST /appointments/{id}/reschedule/respond
{ "action": "accept" | "reject", "reason": "可选" }
```

建议语义：

- `accept`：`requestedTime = proposedTime`、`proposedTime = null`、
  `status = 1 CONFIRMED`（导师提出新时间即视为同意该时间，学生接受后双方达成一致）；
- `reject`：`proposedTime = null`、保留原 `requestedTime`、状态仍 `0 PENDING`，
  学生可继续取消或等待导师确认原时间；
- 需要新增列保存学生响应与原因（`reschedule_response` / `reschedule_reason`）。

> 产品确认上述四点后再实现；当前前端继续展示「导师建议改期至 …」并提示联系导师。

## 7. 预约材料预览 / 下载（已有接口，前端已接入）

学生没有 `file:list`，**不要**调用通用 `/files/{id}/preview|download`。正确接口：

```http
GET /appointments/{id}/materials/{materialId}/preview
GET /appointments/{id}/materials/{materialId}/download
GET /appointments/{id}/record/materials/{materialId}/preview
GET /appointments/{id}/record/materials/{materialId}/download
```

- 权限码：`appointment:list`；可见性包含申请人本人。
- 前端已按 `material.source`（`appointment` / `record`）选择对应路径。
- 支持多份材料上传：`POST /files` 一次 1–10 个文件 → 逐个
  `POST /appointments/{id}/materials` 挂接。

## 8. 统一认证登录（已有接口，前端已接入）

- `POST /auth/login` 响应新增 `loginSource` / `ssoUnavailable` / `isDefaultPwd`。
- 前端已实现：
  - `ssoUnavailable === true` → 顶部黄色提示「统一认证暂不可用，已使用本地密码登录」；
  - `isDefaultPwd === true` → 顶部提示「仍在使用初始密码，请到统一认证平台修改」；
  - `GET /auth/profile.user.authSource === 'sso'` → 隐藏个人中心「修改密码」入口；
  - 错误码 20108–20113 直接展示后端稳定文案。
- 无后端缺口。
